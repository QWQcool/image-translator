## 二、缺陷清单

### P1 空间描述无法清空（前端「清空描述并保存」无效）

- 位置：`src/app/api/spaces/[id]/route.ts` PATCH（description 归一化 + COALESCE 更新）
- 复现：
  1. `PATCH /api/spaces/:id {"description":"有描述"}` → 200，描述已写入
  2. `PATCH /api/spaces/:id {"description":null}` → **400 `{"error":"没有需要更新的字段"}`**
  3. `PATCH /api/spaces/:id {"description":""}` → 200，但 `GET` 回读描述仍为旧值
- 期望：接口注释明确「description 允许传 null 表示清空描述」，null/空串应把 `description` 置 NULL
- 实际根因：`body.description === null` 被归一化为 `undefined`（只发 null 时整包判为「没有字段」→ 400）；
  空串被转为 `null` 后又走 `COALESCE(?, description)` → 保留旧值。两条清空路径都不通。
- 影响：用户清空空间描述后保存，重新打开描述仍在。

### P2 空间序号「不复用」承诺与实现不符（删除最大序号后重建会复用）

- 位置：`src/app/api/spaces/route.ts` `nextSpaceNo()`（取现存最大 NN + 1）
- 复现：建空间得 `20260904-04` → 删除该空间 → 再建空间 → **又得到 `20260904-04`**
- 期望：README 与代码注释均声称「序号不复用、不回退，删除最大序号空间后重建 = MAX+1」
- 实际根因：`MAX(现存 space_no)+1` 在删除的恰好是当日最大序号时会回收该号；只有删除非最大序号时才表现为不复用
- 影响：低——序号语义与文档不一致，历史链接/口头引用可能指向新空间。
- 修复建议：把「当日已发最大 NN」持久化（如站点配置键或独立计数表），生成时取 `max(已发最大, 现存最大)+1`。

### 观察项（非缺陷，建议统一口径）

- 空间 API 返回的 `tags` 是 JSON **字符串**（列表/详情/建空间均是），前端自行 `JSON.parse`；
  `distinctTags` 却是数组。建议文档明确或统一为数组。
- 两步 OCR 链路（检测出框+补提取）不产出 `ai_context` 图像描述，仅单步视觉 OCR 有；
  同一页两种引擎跑出的翻译上下文不一致。可让检测响应也支持 description。

## 三、功能缺口 / 产品建议

1. **一键机翻完成后不联动空间进度**（现状确认）：逐页 OCR → 采纳 → 译文落库全部成功后，
   空间 progress 保持不变。建议：全部页有译文时自动置「已翻译」，或完成后弹提示让用户一键推进。
2. 描述清空（= 缺陷 P1）。
3. 序号复用（= 缺陷 P2）。
4. OCR 响应把「与既有标号过近被跳过」的提案直接剔除，前端无从提示「跳过了 N 个重复块」；
   建议返回 `skippedCount`。
5. 运维提示（非产品缺陷）：同一项目目录同时跑两个 `next dev` 会共享 `.next` 并互相破坏路由
   （本次实测：后起实例全 API 404）。多实例测试必须各自独立 distDir。建议写进开发者文档。
