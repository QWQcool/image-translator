## P5 — 网页端 LabelPlus + 简易嵌字图编（可做，非上线阻塞）

> **结论（2026-09-01）**：两项都做，但**不要做成 Photopea**。
>
> 专业漫画/插图翻译工作流是「**标号翻译** → **嵌字修图**」。当前编辑器是第三种东西：在图上画框、用底色盖原文、框内排译文。它适合海报/推文这种「一块色块就能盖住」的图，盖不住渐变、纹理、异形气泡。
>
> 对照实现：
> - **桌面 LabelPlus**（[帮助文档](https://labelplus.gitbook.io/labelplus_help)）才是功能标尺，不是 labelplus_web。
> - [labelplus_web](https://github.com/amer1ns/labelplus_web) 只做了标号 + 录入 + 两种分组（框内/框外），单用户写本地 txt。交互可借鉴，**按桌面版补齐**，并加上本站已有的多人协作。
> - [Photopea](https://www.photopea.com/) 禁止复刻、禁止 iframe。开源仿 PS 评估见下表。
>
> **依赖**：P1.5 原图直出应先完成。嵌字必须在原图上涂改，压缩 WebP 再修会糊。
> **测试素材**：`PictureTest/`（原有 8 张宣传海报 + 后补的对话框/框外旁白/推文卡/竖条漫画/小图章）。

三种工具并存，不要互相替换：

| 入口 | 干什么 | 什么时候用 |
| --- | --- | --- |
| 现有框选编辑器 | 画框 + 底色盖字 + 框内排译文 | 色块/纯色底能直接盖住原文 |
| **LabelPlus 标号器** | 点气泡中心放编号、分组（框内/框外）、右侧录译文 | 翻译/校对；图还没嵌字 |
| **简易嵌字图编** | 图层 + 涂白/橡皮/仿制 + 文字层 | 标号完成后真正改像素 |

网页里有标号器之后，**不再依赖导出 txt 才能标号**。LabelPlus txt 仍建议保留为可选导出：有人要用桌面 PS + [PS-Script](https://github.com/LabelPlus/PS-Script) 时还能接上。

### P5.1 LabelPlus 标号器（按桌面版做，比 labelplus_web 完整）

labelplus_web ≈ 桌面版的 30%：两种分组、标号、录入、写 txt。桌面版还有四种模式、1–9 分组、审校、大量快捷键、预置短语、临时隐号。本站还多了协作，可以比桌面更好。

对照：[操作模式](https://labelplus.gitbook.io/labelplus_help/ji-zhong-cao-zuo-mo-shi-jie-shao) · [快捷键](https://labelplus.gitbook.io/labelplus_help/kuai-jie-jian-lie-biao) · [分组](https://labelplus.gitbook.io/labelplus_help/fen-zu-gong-neng)

- [ ] **35. 标号数据模型**
  - 文件：`src/lib/types.ts`、`src/lib/db.ts`
  - 现有 `annotations` 是矩形框。LabelPlus 是**点**（`x,y` ∈ 0~1）+ **分组 1–9** + 顺序 + 文本。
  - `kind`：`box` / `pin`（默认 `box` 兼容旧数据）；点标号 `w/h` 存 0
  - `group_id` 1–9；空间级分组名（默认 `1=框内` `2=框外`，可增删改名，最多 9）
  - **比桌面多的字段（建议一起建）**：`source_text`（原文，OCR 写入）、`comment`（审校批注）、`updated_by`
  - 不要为标号另起一套完全不通的表

- [ ] **36. 四种模式 + 标号 UX（对齐桌面 Q/W/E/R）**
  - 同一编辑器顶栏切换：`框选` | `浏览` | `标号` | `录入` | `审校` | `嵌字`
  - **标号模式**：单击空白即下标（数字角标），拖动移动，点选；不必按 Ctrl（对齐桌面 Label 模式）
  - **录入模式**：右清单按编号列译文；切标号时画布**跟到该点**；Ctrl+Enter 下一项（桌面习惯）
  - **审校模式**：标号旁显示分组名；鼠标悬停自动选中；可写 `comment`
  - **浏览模式**：全能，偏查看
  - 键盘：`1–9` 设默认分组 / 改选中分组；`← →` 翻图；`↑ ↓` 切标号；`V` 临时隐号；`C` 显示分组名；`Del` 删标号
  - 框内红 / 框外蓝（其余组自配色）；滚轮缩放、空格拖动画布（复用现有视口）

- [ ] **37. 录入效率（比 labelplus_web 强的部分）**
  - 底部/侧栏图条，空间内连续翻页
  - 自动保存（复用 `/api/items/:id/annotations`）
  - **预置短语**（桌面的 A 键）：空间级短句，如「……」「（沉默）」一键插入
  - 可选：**原文 + 译文双栏**（桌面只有译文；OCR 来了原文栏就有用）
  - 按译文搜索当前空间（可与 P4-30 合并）

- [ ] **38. LabelPlus `翻译_0.txt` 导入 / 导出**
  - 文件：`src/app/api/spaces/[id]/export/route.ts`、`ExportMenu.tsx`；新增 import API
  - 官方 1.x 格式（UTF-8 BOM），与 PS-Script 兼容：
    ```
    1,0
    -
    框内
    框外
    -
    Default Comment
    >>>>>>>>[001.png]<<<<<<<<
    ----------------[1]----------------[0.456,0.210,1]
    对话文字
    ```
  - 文件名用 `original_name`，没有则 `filename`
  - 导入按文件名匹配进空间。日常标号不必导出；这条留给仍用桌面 PS 的人

- [ ] **39. 与框选编辑器共存 + 协作**
  - 同一张图 `box` 与 `pin` 并存，保存按 `kind` 分发
  - 权限走现有接口；P1-8 落地后全员可标号
  - 标号列表显示最后编辑者（`updated_by`）——桌面版没有、协作站点该有

### P5.2 简易嵌字图编（不是 Photopea，工作量明显更大）

> **目标**：嵌字员在浏览器里完成「涂掉原文 → 放下译文 → 导出成品图」。
> **非目标**：滤镜库、智能对象、曲线/色阶、钢笔路径、完整 PSD 兼容、内容识别填充。那些是 Photopea 十年的产品，本站 100 人圈子用不上。

- [ ] **40. 图层画布骨架**
  - 新页：`src/app/(app)/typeset/[itemId]/`（或编辑器第三模式）
  - 技术：自研 Canvas + 图层栈（不要嵌 Photopea，不要整仓拷 miniPaint）
  - 图层：`背景（原图，默认锁）` / `涂改（像素）` / `文字（矢量，可再编）`
  - 撤销/重做（命令栈，至少 50 步）；缩放/平移与标号器同一套手感
  - ⚠️ 大图：原图直出后 2–8MB、边长 2000–4000 常见。涂改层用与画布同尺寸的 offscreen canvas，不要把 4K 原图像素在 React state 里传来传去

- [ ] **41. 嵌字工具集（第一期就这些）**
  - **画笔 / 橡皮**：硬度、大小、颜色；橡皮只擦涂改层
  - **吸管**：从原图取色（气泡底色、描边色）
  - **矩形/套索选区 + 填充**：框内对白的主路径（选气泡 → 填白/填取样色）
  - **仿制图章（简化）**：Alt 取源、涂抹；对付 `PictureTest` 里那些渐变海报（纯白盖不住）
  - **文字工具**：横排；字号/字体/颜色/描边/行距；可选竖排（漫画旁白）
  - 明确不做：魔棒自动抠气泡、内容识别填充、液化、完整调整图层

- [ ] **42. 从标号一键生成文字层**
  - 读该图所有 `kind=pin` 的标号，在 `(x,y)` 生成文字图层，内容=译文，分组决定默认样式（框内 vs 框外字体/颜色）
  - 这是「网页有 LabelPlus 就不必导出 txt」的真正闭环：标号员标完，嵌字员打开图编，字已经在对应位置

- [ ] **43. 保存与导出**
  - 图层草稿：JSON + 涂改层 PNG，按 `item_id` 存 `data/typeset/`（或 blob 字段）；刷新可续编
  - 合成导出：扁平 PNG（给下游发图）；可选把成品写回该空间一张新图，不覆盖原图
  - PSD 导出（可选、后做）：`ag-psd` 能出「背景 + 文字层」的浅 PSD，给仍用桌面 PS 精修的人。不要承诺 Photopea 级 PSD 往返

- [ ] **44. 明确不做 / 以后再说**
  - ❌ 复刻 Photopea 或 iframe 嵌入 photopea.com
  - ❌ 服务端 GPU 修复、自动去字、OCR 自动标号（可另开条目，不塞进本期）
  - ❌ 把现有框选编辑器删掉（海报/推文仍是最快路径）
  - 以后若要「再聪明一点」：魔棒按颜色扩选气泡、从标号点向内 flood-fill 涂白（LabelPlus PS 脚本的实验功能）。那是 41 的增强，不是 40 的前提

**分期建议**：A 视觉 → C 原图 → 35–37 标号四种模式可用 → 38 txt → 40–42 最小嵌字 → 41 仿制与 43 草稿 → F 才做 OCR/去字。不要第一期堆 PSD/竖排/魔棒。

### P5.3 OCR 自动标号 + 自动去字（后做，已确认要做）

> 人工标号（D）先能用。这两条是加速，必须**可撤销、默认不覆盖已有标号**。
>
> 参考管线（开源漫画翻译站都走这条）：**检测框 → OCR →（可选翻译）→ 去字 inpaint → 嵌字**。
> - 检测：Comic Text Detector 一类（[manga-image-translator](https://github.com/zyddnys/manga-image-translator) 生态，注意 GPL 权重）
> - OCR：印刷/中英用 RapidOCR（Apache）；日漫竖排/假名用 [manga-ocr](https://huggingface.co/onnx-community/manga-ocr-base-ONNX)（MIT）
> - 去字：[LaMa](https://github.com/advimman/lama) ONNX（Apache），可浏览器或本机 sidecar；薄字也可先用 OpenCV Telea 作降级

- [ ] **49. OCR 自动标号（人机确认）**
  - 对当前图：检出文本块 → 在块中心落 `pin` → `source_text` 填识别结果，`text`（译文）留空
  - UI：每条可勾选「采纳 / 丢掉 / 改分组」；**不自动保存未确认结果**
  - 已有人工标号的图：默认只补「没有标号的区域」，不冲掉手标
  - 部署倾向：ONNX **本机 sidecar**（CPU 即可），不要第一期塞进浏览器（manga-ocr ~400MB）
  - `PictureTest/lp-speech-bubbles.png`、`tall-manga-strip.png` 作回归

- [ ] **50. 自动去字（inpaint）**
  - 掩膜来源：OCR 框外扩 / 用户选区 / 标号点 flood-fill（后做）
  - 第一期：LaMa ONNX 出一张「去字底图」作为嵌字编辑器的涂改层，**不覆盖原图 asset**
  - 降级：OpenCV.js Telea（纯白气泡够用，渐变海报不够）
  - 用户必须能「丢弃这次去字」回到原图

- [ ] **51. 自动翻译（可选，更后）**
  - OCR 原文 → 调翻译 API 填 `text`；要单独预算与开关
  - 不和 49 绑死：圈子可能只想「认出日文」，译文自己写

⚠️ GPL：Comic Text Detector 若带 GPL 权重，**不要链进主站 MIT/未定协议源码**；做成独立 sidecar 进程、用户可关。RapidOCR / LaMa / manga-ocr 协议友好，优先用它们。

## 三个容易踩的坑

1. **媒体接口千万别放开**：保持 401 校验 + `Cache-Control: private`，否则图片 URL 裸奔。
2. **HTTPS 是登录前提**：`Secure` Cookie 在纯 HTTP 下不生效，必须域名+证书（正式）或改代码/自签（临时）。
3. **原图直出后磁盘涨得快**：存量超系统盘 60% 前升级套餐或加盘（当前删图模式存量 10~30GB，无忧）。
