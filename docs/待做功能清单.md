# 待做功能清单

> 已确认的决策：国内部署 · **全部共享空间（无私人空间）** · **图片全部公开** ·
> **未注册访客只能浏览** · 推特 API **由网站统一指定一批账号采集**
>
> 规模：注册用户约 100 多人，日均 1000 名未注册访客
>
> 每条都标注了要改的文件和注意点，按顺序做即可。P0 是上线阻塞项。

## P0 — 未注册访客浏览（阻塞上线，必须先做）

> **当前状态：所有接口强制登录，未登录一律 401/404。**
> 最致命的是图片媒体接口也要求登录，访客会看到一片空白。

- [ ] **1. 媒体接口放开鉴权**
  - 文件：`src/app/api/media/[...path]/route.ts`
  - 删除开头的 `getCurrentUser()` 401 检查（图片全部公开）
  - 把响应头 `'Cache-Control': 'private, max-age=31536000, immutable'`
    改成 **`public`** —— 否则 CDN 不会缓存，1000 访客/天会打穿服务器带宽
  - ⚠️ `public` 一旦被 CDN 缓存就很难收回，确认图片确实要完全公开再改

- [ ] **2. 权限层支持「未登录」**
  - 文件：`src/lib/permissions.ts`
  - `getSpaceAccess(spaceId, userId)` 的 `userId` 改为 `number | null`
  - 未登录时：`public` 空间返回 `viewer`，`private` 空间返回 `null`
  - 关键分支：
    ```ts
    const member = userId === null ? undefined : /* 查 space_members */;
    // ...
    else if (userId !== null && space.owner_id === userId) role = 'owner';
    else if (space.visibility === 'public') { role = 'viewer'; isMember = false; }
    else return null;   // 未登录 + 私有空间
    ```

- [ ] **3. 空间列表接口对访客开放**
  - 文件：`src/app/api/spaces/route.ts` → `GET`
  - `getCurrentUser()` 可能为 `null`
  - 未登录时只返回 `visibility='public'` 的空间
  - 现有一条 SQL 用了三个 `user.id` 参数，未登录需要单独分支处理

- [ ] **4. 空间详情接口对访客开放**
  - 文件：`src/app/api/spaces/[id]/route.ts` → `GET`
  - 允许未登录读取公开空间；`PATCH` / `DELETE` 仍要求登录与权限

- [ ] **5. 条目与标注的读取接口对访客开放**
  - `src/app/api/items/[id]/route.ts` → `GET`
  - `src/app/api/items/[id]/annotations/route.ts` → `GET`
  - 写入（`PATCH` / `DELETE` / `PUT`）保持原有鉴权不变

- [ ] **6. 导出接口对未登录拒绝**
  - 文件：`src/app/api/spaces/[id]/export/route.ts`
  - 用户要求「未注册只能浏览」→ 未登录返回 401

- [ ] **7. 布局不再强制跳登录**
  - 文件：`src/app/(app)/layout.tsx`
  - 当前 `if (!user) redirect('/login')`，改为未登录也正常渲染

- [ ] **8. 顶栏未登录态**
  - 文件：`src/components/TopBar.tsx`
  - `user` 为 `null` 时显示「登录 / 注册」按钮，而不是用户名 + 退出

- [ ] **9. 首页分流调整**
  - 文件：`src/app/page.tsx`
  - 未登录时跳转到 `/spaces`（公开浏览入口），而不是 `/login`

- [ ] **10. 各页面隐藏编辑入口**
  - `src/app/(app)/spaces/SpacesClient.tsx`：隐藏「新建空间」「编辑」「删除」
  - `src/app/(app)/spaces/[spaceId]/SpaceDetailClient.tsx`：隐藏「添加图片」「成员」「删除空间」
  - `src/app/(app)/annotate/[itemId]/AnnotationEditor.tsx`：未登录自动只读
    （`access.canEdit === false` 的只读分支已经写好，只需确保接口读得到数据）

- [ ] **11. 登录后跳回原页面**
  - 文件：`src/app/login/page.tsx`、`src/app/login/AuthForm.tsx`

## P2 — 推特 API 采集器

> 数据库字段与唯一索引**已预留**：`assets.source_url` / `source_author` / `source_post_id`，
> 且 `(owner_id, source_post_id)` 上有唯一索引，增量去重可以直接用 `INSERT OR IGNORE`。

- [ ] **15. 采集源管理表**
  - 建议新建：
    ```sql
    CREATE TABLE crawl_sources (
      id              INTEGER PRIMARY KEY AUTOINCREMENT,
      username        TEXT NOT NULL UNIQUE,
      x_user_id       TEXT,
      enabled         INTEGER NOT NULL DEFAULT 1,
      last_post_id    TEXT,
      last_crawled_at TEXT
    );
    ```
  - 加进 `src/lib/db.ts` 的 `SCHEMA`（`CREATE TABLE IF NOT EXISTS`）

- [ ] **16. 采集脚本**
  - 新建 `crawler/index.ts`
  - 遍历 `enabled=1` 的账号，调：
    ```
    GET /2/users/{x_user_id}/tweets
      ?max_results=100
      &exclude=retweets,replies
      &expansions=attachments.media_keys
      &media.fields=media_key,type,url,preview_image_url,width,height,alt_text
      &tweet.fields=created_at,attachments
      &since_id={last_post_id}
    ```
  - **只处理 `type=photo`**（video / animated_gif 的 `url` 字段为空，需要读 variants，先不做）
  - 下载图片 → `storeImage()` → 写 `assets`，`visibility='shared'`
  - 服务账号作为 owner（需要一个系统用户，或 `owner_id` 允许为 NULL）

- [ ] **17. 速率限制与退避**
  - 读响应头 `x-rate-limit-remaining` / `x-rate-limit-reset`
  - 遇到 429 等到 reset 时间点再继续，配合指数退避
  - 应用级限额 10,000 次/15min，实际瓶颈是费用不是速率

- [ ] **18. 预算护栏（必做）**
  - 环境变量 `MAX_POSTS_PER_RUN` 限制单次任务读取条数
  - 超限立即停止并记录
  - 控制台另外设置 spending limit 兜底

- [ ] **19. 定时任务**
  - `node-cron` 或系统 crontab
  - **建议每 3 天一次**（每天约 ¥270/月，每 3 天约 ¥90/月，内容晚 3 天用户几乎无感）

- [ ] **20. 环境变量**

## 两个容易踩的坑

1. **媒体接口的 `Cache-Control` 一定要改成 `public`**，否则 CDN 不缓存，
   1000 访客/天 × 突发加载会把服务器带宽打满（实测瞬时峰值可达 ~84 Mbps）。

2. **图片全部公开 = 任何人拿到 URL 都能访问**。这是当前决策的正确结果，
   但要知道将来若出现私有内容，必须额外加签名 URL 机制（现在可以不管）。
